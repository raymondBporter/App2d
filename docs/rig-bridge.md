# Noodle bone editor to authored character model

The authored `CharacterModel` is the runtime rig. The older `PuppetDefinition` already converts to it through `PuppetImport`. The Noodle bone editor now exports its current hierarchy through `RigAuthoredBridge2D`: run `App2d.Noodle --bones`, edit the rig, then press **Ctrl+S** to save a model JSON file. The exported file can be loaded by the authored model pipeline.

Each Noodle bone becomes one authored bone control with a rest origin, angle, and length. Each shape becomes a drawing part attached directly to that bone's local XY frame, with its local offset and angle. Noodle pixels become authored units at 100 pixels per unit. `rotate` tracks on bone controls carry descendants and attached shapes with them; the deterministic `App2d.Noodle --check` command compares both paths before and after parent and child rotations. Both editors use Core's `BoneFrame2D` for a bone's world origin, angle, and tip.

This is a one-way rest-pose export. Noodle has no clip authoring or JSON document format yet. The bridge does not automatically create constraints or per-bone physics. In Studio, an exported rig with connected segment tips can now use **Make IK constraint**. This selects Core's bone-frame solver; the legacy point solver remains separate for compatibility. `--check` also exports a two-segment linkage, adds a typed bone constraint and compares its solved bones and artwork against the corresponding Noodle pose. A collision-only Noodle shape is exported as a hidden drawing part; it does not automatically become a gameplay collider. Color alpha is not represented by `PuppetPart` and is omitted.

Studio's older models still use point controls and optional two-control part orientation. New bones and frame-attached parts coexist with them in one authored model and one pose evaluator. The shared `RigConstraintEvaluator` runs IK goals and contact pins after FK and before drawing. Path constraints, physics, Noodle procedural clip conversion and its skin deformation remain separate migration steps; see [the resource roadmap](character-resources.md).
